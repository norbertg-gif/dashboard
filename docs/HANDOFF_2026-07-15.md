# Handoff: Trading Dashboard

## 1. KONTEXT ÚLOHY

Projekt je osobný, single-user trading dashboard pre monitoring eToro portfólií, technickú analýzu, DIP scanner a interpretačné analytické vrstvy. Repozitár je `norbertg-gif/dashboard`, aktuálne používaná vetva je `main` a produkcia beží na Render.com. Rozhranie je v slovenčine; dáta pochádzajú najmä z eToro proxy, Yahoo Finance/yfinance, Massive a doplnkových analytických zdrojov.

### Fair Value beta

Implementovaný je lazy endpoint `GET /api/ticker/fair-value/{symbol}` a karta `Férová hodnota beta` v Analytike. Karta sa načíta až po vyžiadaní a výsledok sa ukladá do diskovej cache s TTL 24 hodín. Používa dostupné dáta z Finnhub a voliteľný fallback z FMP; kľúče sa čítajú iba z env premenných.

Použité modely sú orientačné: Graham number, Lynch/PEG, zjednodušený DCF a analytický price target ako samostatný externý kontext. Analytický cieľ sa nemieša do mechanického pásma. Graham sa vynechá pri extrémne vysokom P/B a Lynch/PEG pri PEG nad limitom; pri nedostatku vhodných modelov UI radšej ukáže `insufficient_models` než zavádzajúce číslo.

## 3. KĽÚČOVÉ ROZHODNUTIA

Tieto body sú explicitné používateľské preferencie a nemajú sa meniť bez predchádzajúceho odsúhlasenia:

- **Read-only rozsah:** aplikácia nesmie zadávať, rušiť ani meniť eToro obchody. Objednávky sú iba zobrazované.
- **Bezpečnosť:** eToro kľúče, Basic Auth údaje a verejný API token patria do env premenných, nie do zdrojového kódu ani dokumentácie. Relevantné názvy sú `ETORO_API_KEY_1`, `ETORO_USER_KEY_1`, `DASH_USER`, `DASH_PASS`, `PUBLIC_API_TOKEN`, `FINNHUB_API_KEY`, `MASSIVE_API_KEY`.
- **Jeden zdroj pravdy pre portfólio:** `/api/etoro/portfolio` poskytuje processed snapshot pre portfólio aj kompatibilné endpointy. Nevytvárať paralelný raw-cache výpočet.
- **Dlhodobý štýl:** používateľ investuje s horizontom približne 1–3 roky alebo dlhšie. 90D validácia je analytický checkpoint, nie obchodný horizont.
- **Predikcia je binárna:** model má odpovedať hore/dole; prediktívny graf je analytická pomôcka, nie automatický poradca.
- **Signály nie sú automatický nákup:** C1–C4 a DIP skóre pomáhajú vybrať kandidáta; pred DCA sa má overiť graf a kontext.
- **Krypto ignorovať v DIP/AI investičnej analýze:** relevantné investičné odporúčania majú prioritne pracovať so Stock/ETF.
- **Full diagnostic export:** AI export sa zatiaľ nedelí na snapshot/diagnostic; používateľ chce raz týždenne celý diagnostický výstup.
- **UI smerovanie:** ďalšie zmeny majú skôr zjednodušovať a skrývať vizuálny šum, nie pridávať ďalšie indikátory. Basic má byť praktický, Advanced ponecháva detailné vrstvy.
- **Fair value je iba orientačná beta vrstva:** nesmie vstupovať do C1–C4, scanner tieru, Verdiktu ani účtovníctva.
- **Daily P/L:** pre Stock/ETF sa približuje eToro výpočtom z eToro live ceny a predchádzajúceho market close z Massive/yfinance. eToro API neposiela hotové `dailyPnL`; presná interná eToro hodnota sa nesľubuje.
- **Daily cutoff:** pri interpretácii daily percent treba počítať s vlastným eToro denným cutoffom okolo newyorskej uzávierky. Trhový close a eToro refresh môžu vytvoriť malé odchýlky, najmä pri tituloch obchodovaných 24/5.
- **Frontend bez bundlera:** moduly sú klasické `<script>` tagy so zdieľaným globálnym scope. `main.js` zostáva posledný. Pri JS/CSS zmene treba bumpnúť spoločný `?v=` token všetkých frontend tagov.

Zamietnuté alebo odložené alternatívy: automatické obchodovanie a one-click trading; návrat k dashboardu plnému indikátorov; ďalšie ladenie predikcie iba cez technické cenové features bez novej informačnej hodnoty; trvalé serverové push alerty; druhý samostatný portfóliový výpočet pre Inbox alebo AI export.

## 4. AKTUÁLNY STAV PROSTREDIA

### Runtime a deploy

- Python runtime: 3.14.x podľa `.python-version`; lokálne sa používa Python 3.14.
- Backend: FastAPI + Uvicorn, pandas/numpy, scikit-learn, yfinance, hmmlearn.
- Frontend: vanilla HTML/CSS/JavaScript, Lightweight Charts 5.2.0, SheetJS.
- Produkcia: Render.com Web Service s persistentným `/data` diskom.
- Produkčný deploy sa spúšťa pushom na `main` podľa [render.yaml](../render.yaml).
- Lokálny eToro proxy server je in-process thread na `localhost:8765`; v produkcii sa nemá spúšťať ako samostatný proces.
- Node je lokálne dostupný cez `C:\Program Files\nodejs\node.exe`; PowerShell wrapper `npm.ps1` môže byť blokovaný Execution Policy, preto používať `node.exe` alebo `npm.cmd`.

### Overené vs. neoverené

Overené: posledný commit je pushnutý na `origin/main`; Python syntax backendu; syntax `frontend/js/predictive.js`; regresné testy 16/16; smoke test 19/19; fair-value karta je lazy-loadovaná, cacheovaná a fail-soft pri chýbajúcich API dátach; AMD problém s absurdným pásmom bol opravený filtrovaním nevhodných heuristík.

Nie je v tomto handoffe samostatne overené: aktuálny produkčný Render deploy po commite `910b777`; živé odpovede všetkých externých providerov v danom okamihu; presnosť fair-value modelov ako investičnej metriky.

Známe drobné resty: niekoľko starších dead-code/dead-route kúskov ostáva zámerne; `get_public_portfolio` má staršiu mierne odlišnú summary logiku; lokálny smoke test bez eToro proxy nevie overiť živé hodnoty; HMM/regime a ML predictive vrstvy sú v low-memory profile vypnuté, signal analytics zostávajú dostupné.

## 5. KDE SME SKONČILI + ĎALŠIE KROKY

### Presne rozpracovaná vec

Posledná dokončená vec je fair-value beta. Po Render deployi treba v Analytike overiť AMD, klasickejšiu akciu a titul bez dostupných dát: kliknúť na `Načítať modely`, skontrolovať oddelenie analytického cieľa od modelového pásma, označenie vynechaných modelov, svetlý/tmavý režim a opakované načítanie z 24h cache.

### Otvorené úlohy podľa priority

**P1 — Produkčné overenie fair value:** potvrdiť AMD bez absurdného Graham/Lynch pásma; overiť text a fail-soft správanie pri limitoch providerov.

**P2 — Zjednodušenie analytického UI:** ďalej ladiť Basic/Advanced podľa reálneho používania; zachovať prediktívny graf, ale analytickú záložku držať prehľadnú; rozšírené vrstvy ponechať v Advanced.

**P3 — Kvalita signálov:** pokračovať v zbere 30D/60D/90D outcome dát a regime kontextu. Nové features pridávať iba vtedy, keď prinášajú novú informačnú hodnotu, napríklad relatívnu silu, fundamenty alebo news.

**P4 — Údržba a bezpečnosť:** zvážiť token verejného API výhradne v hlavičke; zjednotiť verejný portfolio summary helper; dead code odstraňovať až po potvrdení call-sites a testoch.

**P5 — Nápady bez záväzku:** sektorová koncentrácia môže byť užitočnejšia než ďalší heatmap eye-candy; PWA alebo AI interpretácia verdiktu sú voliteľné a nesmú zvyšovať pamäťovú stopu Renderu bez merateľného prínosu.
